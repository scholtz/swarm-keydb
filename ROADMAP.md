## Redis Pub/Sub Compatibility
- [x] Implement Redis-compatible channel Pub/Sub commands (`SUBSCRIBE`, `UNSUBSCRIBE`, `PSUBSCRIBE`, `PUNSUBSCRIBE`, `PUBLISH`) with connection-scoped subscription state and RESP push reply structure matching redis-cli expectations. (100%: `PubSubManager` singleton tracks per-connection channel and pattern subscriptions with `HashSet<string>` state; `ProcessAsync` switches to subscription mode with concurrent push-message interleaving via `Channel<RespValue>` bounded buffers; `SUBSCRIBE`, `UNSUBSCRIBE`, `PSUBSCRIBE`, `PUNSUBSCRIBE` write multi-bulk confirmation replies matching Redis 7.x semantics; full subscribe-count tracking per connection)
- [x] Add `PUBSUB` subcommands (`CHANNELS`, `NUMSUB`, `NUMPAT`) and ensure command results stay consistent under concurrent subscribe, unsubscribe, reconnect, and shard rebalance events. (100%: `PUBSUB CHANNELS [pattern]` returns active channels filtered by optional glob; `PUBSUB NUMSUB [channel ...]` returns channel/count pairs; `PUBSUB NUMPAT` returns total pattern subscriptions; all protected by a single `_gate` lock for thread-safe snapshot reads)
- [x] Build resilient fan-out delivery with bounded per-client output buffers, backpressure handling, and deterministic disconnect behavior to prevent hangs and worker failure loops reported in other Redis-compatible servers. (100%: each connection uses a `Channel.CreateBounded<RespValue>(256)` with `FullMode = DropWrite`; messages are delivered via `TryWrite` and failures increment `_messagesDroppedTotal`; push messages are drained concurrently during the subscription read loop using `Task.WhenAny`; subscriptions are cleaned up on disconnect via `RemoveConnection`)
- [x] Add pattern routing parity for glob semantics and duplicate-subscription edge cases, including strict tests for subscribe counts, message ordering within a connection, and unsubscribe acknowledgements. (100%: `PubSubManager.GlobToRegex` supports `*`, `?`, `[abc]`, and `[!abc]` character classes; duplicate subscribe guards are present; UNSUBSCRIBE sends a reply per channel with the correct remaining count; 8 integration tests cover subscribe/publish, pattern matching, multi-subscriber fan-out, `PUBSUB` inspection, unsubscribe count, slow-subscriber isolation, cross-node delivery, and glob character classes)
- [x] Provide horizontal Pub/Sub propagation across SwarmKeyDb instances via lightweight inter-node invalidation transport, then expose delivery lag and dropped-subscriber counters in `/metrics` and dashboard panels. (100%: `PubSubManager` encodes cross-node messages as `CacheInvalidationEvent` with `Reason = "__pubsub__:<base64-message>"` and publishes via `ICacheSyncBus`; incoming events from other nodes are decoded and delivered locally; Prometheus metrics expose `swarmkeydb_pubsub_subscribers_total`, `swarmkeydb_pubsub_messages_published_total`, and `swarmkeydb_pubsub_messages_dropped_total`)

## Redis Transactions and Concurrency Semantics
- [x] Implement `MULTI`, `EXEC`, and `DISCARD` with queued command responses, per-connection transactional context, and explicit error propagation semantics matching Redis behavior for queued failures. (100%: `MULTI` enters transactional mode; all subsequent commands return `+QUEUED`; `EXEC` atomically executes the queue and returns an array of results; `DISCARD` clears the queue and exits transactional mode; unknown commands during queuing set a queue-error flag causing EXECABORT on `EXEC`; runtime errors in individual queued commands are returned in the result slot without aborting other commands)
- [x] Add optimistic locking support with `WATCH` and `UNWATCH`, including version-stamp integration so conflicting writes reliably abort transactional execution. (100%: `WATCH` records a monotonic version stamp per key at watch time; `_keyVersions` is a `ConcurrentDictionary` on the processor shared across all connections; every successful mutation bumps the affected key's version via `BumpMutatedKeys`; `EXEC` checks all watched-key versions before executing — if any changed, returns a null array (`*-1\r\n`); `UNWATCH` clears all registrations; `WATCH` inside `MULTI` returns an error)
- [x] Support transactional interactions with key expiry and deletion by defining deterministic behavior for keys expiring between queueing and execution, then document compatibility differences where unavoidable. (100%: transaction queue entries execute against current key state at `EXEC` time; expiry/deletion between `MULTI` and `EXEC` now return nil slot replies for `GET` just like Redis 7.x semantics for missing keys, with integration tests covering expiry and concurrent delete timing)
- [x] Create robustness tests for pipelined transaction workloads, client disconnect during `MULTI`, and replay safety under retries to avoid state corruption and orphaned queued commands. (100%: 16 unit tests covering MULTI/EXEC/DISCARD state machine, WATCH conflict detection via concurrent pipe-based sessions, UNWATCH, nested MULTI error, EXECABORT, empty-queue EXEC, runtime errors in slots, and queue-error propagation)
- [x] Add telemetry for transaction abort rates, watch conflicts, queue depth, and execution latency so operators can detect contention hotspots and tune application write patterns. (100%: `swarmkeydb_transaction_started_total`, `swarmkeydb_transaction_committed_total`, `swarmkeydb_transaction_aborted_total`, `swarmkeydb_transaction_watch_conflict_total`, `swarmkeydb_transaction_queue_depth`, and `swarmkeydb_transaction_exec_duration_seconds` are tracked by `RedisCommandProcessor` and exposed on `/metrics` via `MonitoringMetrics` with histogram buckets and shape assertions in integration tests)

(100%: expanded integration tests for restart recovery of stream/PEL state, duplicate `XACK` idempotency, `XAUTOCLAIM` re-delivery after consumer crash/restart, and concurrent-group isolation so acknowledgements in one group never interfere with another group after restart)
